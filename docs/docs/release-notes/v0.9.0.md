## Breaking: `riptide.nodes` is removed

Any surviving `riptide.nodes` key fails startup, in every spelling: the name-keyed map, the interim indexed list, camelCase, and the `RIPTIDE_NODES_*` environment form. The error names the offending key and the converter. Run `riptide convert` (or `java -jar riptide.jar convert` on packaged installs) against your 0.8 configuration before upgrading; the [upgrade guide](https://riptide.space/docs/upgrading-from-0.8) has the full path.

Also failing startup, retired earlier in the 0.9 cycle: the fleet-wide `riptide.snmp.poll.refresh-interval-ms` and `riptide.snmp.poll.snapshot-expiry-ms` keys (cadence lives on polling profiles now). The pre-0.1.0 `riptide.snmp.config.definitions` tree keeps its ignored-with-an-error-log behaviour, and its guidance now points at credential sets and the inventory file instead of the removed tree.

## The new model

- Named credential sets (`riptide.snmp.credentials.<name>`) and polling profiles (`riptide.snmp.polling.<name>`) in the main config; agent ranges and exporter enrichment entries in a dedicated inventory file (`riptide.inventory.file`).
- The inventory file is direct-parsed and hot-reloaded on content change. It cannot be supplied via environment variables or `spring.config.import`; a rejected edit keeps the last good inventory serving and raises `inventory.reload.stale`.
- Zero-touch onboarding: a device inside a credentialed range is polled from its first flow, with no per-device configuration. Registration is capped by `riptide.snmp.poll.max-exporters`; concurrency by `pool-width`.
- Per-range cadence: each agent range walks on its polling profile's `refresh-interval`/`snapshot-expiry`, with per-profile `timeout` and `retries`. A per-agent `port` is configurable on the range.
- Enrichment entries match by longest prefix (a bare host beats a covering range; an observation-domain pin beats a wildcard), so one entry can name a whole segment. Interface pins are entry-scoped: on a prefix entry they apply to every covered device.
- Security rule: a v1/v2c credential set on a range wider than a single address fails startup, `enabled` or not. The community would otherwise be sent to any in-range address that emits a flow. Enumerate the devices or move the segment to v3; the converter emits such ranges disabled, with their flows still named and the credential set kept for re-enabling.
- Converted configurations keep every exporter name, including range-scoped ones (prefix entries carry them now); nothing is renamed by the upgrade.
- A config reload rebuilds the inventory against the rebound credential sets and re-resolves already-registered agents, so a credential rotation reaches running walks without a restart. Secret value rotation behind `file://` references needs no reload at all; `sops://` values are cached until a main-config reload; `env://` values are fixed for the process lifetime.

## Hardening

- SNMP walks are bounded poller-side: at most 2 minutes of wall clock and 65,536 rows per walk (walks abandoned at these bounds are counted on their own `snmp.walks.abandoned` meter, distinct from timeouts). snmp4j bounds each round-trip, but the number of round-trips was agent-paced — and since registration follows flows, an in-range address serving a never-ending interface table could previously pin a walker thread forever with unbounded memory growth. Together with the wide-range cleartext rule, this closes both halves of the wide-subnet exposure: what a spoofed in-range flow can extract, and what it can pin.
- Publishing an inventory that silently drops a whole tree is refused; an explicit empty mapping (`agents: {}`) is the authored spelling of a decommission.
- Netmask address spellings (IPv4 and IPv6) are rejected with named remediations: a non-contiguous mask (`10.90.0.0/255.0.255.0`) was previously accepted as a single host at an address the operator never wrote — and, being a single host, bypassed the v1/v2c width rule. Errors for netmasks, leading zeros, wildcards, host-bits-set prefixes and inet_aton shorthand now name the exact string to write instead, and every suggested fix is guaranteed to parse. The legacy converter translates contiguous netmask spellings to CIDR rather than refusing them.
- IPv6 zone ids (`fe80::1%eth0`) are rejected for the opposite reason: matching ignores zones entirely, so a zoned entry matched flows from **any** interface while reading as a per-interface constraint. If your inventory carries one, the first 0.9 boot fails with the zone-free form to write instead; the converter strips the zone rather than refusing, since 0.8's matcher was equally zone-blind and the meaning is unchanged.
- The reloaders now report their own lifecycle truthfully. New `config.reload.dead` and `inventory.reload.dead` gauges read 1 if a poll schedule stopped for good, which was previously invisible. **The stale gauges are now absent rather than 0 when hot-reload is disabled** — a constant 0 read as "the file matches what is serving" for a file that is never read again, so alerting on absence and on `> 0` are now different questions. An orderly shutdown no longer counts a reload failure, and the loader's warnings about an entry are held until that candidate actually publishes, so the log no longer describes configuration that was rejected.

## Known asymmetries, documented

- `sops://` credential rotation requires a config reload or restart, and `env://` a restart; only `file://` rotates with no action at all.
- `/readyz` deliberately excludes ClickHouse and tolerates zero configured receivers, and [the operations guide](https://riptide.space/docs/deploy/operations#health-endpoints--probes) now says so with the reasoning. Flows arrive as UDP push, so a "not ready" collector does not stop the packets; and where Prometheus scrapes through the Service, marking not-ready can take `/metrics` down with it, blinding the signal that explains the outage. Probes are for scheduling; saturation is for alerting on `persister.batch.droppedRows` and `queueDepth`.
- The deb/rpm packages and the container image ship the jar without a `riptide` wrapper; converter invocations there use the `java -jar` form.
