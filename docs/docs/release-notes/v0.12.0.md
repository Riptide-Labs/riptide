## Highlights

**Rollups carry the flow protocol** (#606, closes #583). sFlow scales its counters at ingest and still reports its rate, so multiplying an sFlow row by its sampling interval double-counts it. No rollup carried the column that distinguishes it, so `SUM(bytes * samplingInterval)` — expressible against rollups since v0.11.0 — was only *correct* where sFlow was absent. `flowProtocol` is now a dimension on all four rollups, and the same scaling expression works against either table.

**Earlier versions documented a subset query as the corrected total.** `WHERE flowProtocol != 'SFLOW'` does not return corrected volume; it returns corrected volume of the NetFlow/IPFIX subset, short by every sFlow byte received. On a mixed deployment the raw form deflated and the rollup form inflated, and neither answered "how many bytes crossed the wire". The corrected form is now `sum(bytes * if(flowProtocol = 'SFLOW', 1, samplingInterval))`, and the exclusion is documented as what it actually is.

**IPFIX sampling advertisements are read whatever scope they arrive under** (#604, #597, #595, closes #589 follow-ups; #594). An exporter that states its rate in a Selector Report, or under a scope riptide did not previously look in, was recorded as unsampled and under-reported by its full sampling rate. A learned rate also survives past any exporter's refresh interval rather than expiring between advertisements.

**A suffixed Kubernetes Service no longer crash-loops every collector in the namespace** (#616, closes #612 and #613). Kubernetes injects `{SVCNAME}_PORT` for every Service, and the legacy-key guard's exemption pattern absorbed the field name it was documented as unable to absorb. Any Service whose name carried a suffix took the pods down. The same fix makes the guard actually run at startup, which it had not been doing.

**MCP answers say how far back the table behind them reaches** (#621, closes #609). A short answer no longer reads like a complete one when the table could not cover the range asked for.

## Fixes

- The converter reports a domain-pinned node that overlaps another polled range, instead of emitting a configuration whose polling split is silent (#618).
- The converter guards on what 0.9 actually binds rather than on what the converter maps, so a half-flattened file no longer drops its polling cadence (#617).
- sFlow refuses a frame length no frame could have, rather than recording it (#605).
- Dependency updates across the Maven, Docker and Actions ecosystems (#600, #601, #602, #603).

## Upgrading

**Manage-mode deployments** (`manage-schema: true`, the default) repair their rollups on the next start and need nothing.

**Provisioned deployments** (`manage-schema: false`) need two steps, and the second is easy to miss:

```bash
riptide onboard --admin-url <url> --database <db> --tenant <t> --org <o> \
  --writer-secret <ref> --reader-secret <ref>

systemctl restart riptide      # on each collector
```

Which rollups are usable is decided once at startup, so a collector that declined them keeps answering from raw `flows` until it restarts, however complete the repair was. Until both steps run, a query using `flowProtocol` against a rollup fails with `UNKNOWN_IDENTIFIER`, and every query spanning an hour or more falls back to raw `flows` and is silently truncated at raw retention.

**A corrected-volume query against a rollup now needs two boundary predicates, not one.** `samplingInterval` shipped in v0.11.0 and `flowProtocol` appends after it, so a band of rows knows its rate and not its protocol. Those rows satisfy `'' != 'SFLOW'`, so filtering on the rate alone readmits them:

```sql
SELECT sum(bytes * if(flowProtocol = 'SFLOW', 1, samplingInterval)) AS corrected_bytes
FROM riptide.flows_by_conversation_1m
WHERE timestamp >= now() - INTERVAL 90 DAY
  AND samplingInterval > 0     -- excludes rows aggregated before the rate was carried
  AND flowProtocol != '';      -- excludes rows aggregated before the protocol was carried
```

Against raw `flows` the same scaling expression needs no boundary predicates at all. Do not copy the rollup's `WHERE` clause onto raw `flows`.

**If a 0.8-era configuration is still reaching riptide through the environment, this release will refuse to start.** The `riptide.nodes` flag-day guard was not running at startup at all, so a container carrying `RIPTIDE_NODES_*` booted clean while the operator's device configuration reached nothing. It now fails at startup naming the offending key and the converter. That failure is the intended behaviour and has been since 0.9 — what changed is that it now happens. Run `riptide convert` against the 0.8 configuration before upgrading.

**If you receive sampled IPFIX from exporters that advertise their rate**, more of those advertisements are now read, so sampling-corrected volume changes for them. Raw `bytes` and `packets` are untouched, since riptide has never scaled counters at ingest, and `samplingProvenance` moves off `assumed` for the exporters concerned.

**Rolling back to 0.11.x requires dropping the rollup views first.** An older collector correctly refuses to shrink the sorting key, but then re-points each materialized view at its own narrower `SELECT`, and every row aggregated afterwards takes the reserved empty value in a sorting-key column. Drop the four `_mv` objects before downgrading; the rollup targets and their history are untouched, and the older version recreates the views at its own shape.
